# TRD · 기술 설계

## 실행 구조

- 빈 저장소 기준 기본안은 **Vite + TypeScript + DOM/SVG/CSS**다. 이미 실행 가능한 웹 프로젝트가 있으면 기존 도구를 활용한다.
- 정적 웹 빌드와 상대 경로로 관리하는 에셋을 기본으로 한다. 게임 세션과 진행도는 브라우저에서 관리한다.
- 2.5D 외형은 레이어, 그림자, 캐릭터 및 음식 상태별 이미지로 표현한다. 초기 조작은 DOM/SVG로 검증하고 아트는 쉽게 교체할 수 있게 분리한다.
- npm 명령은 `npm install`, `npm run dev`, `npm run build`, `npm run preview`, `npm test`를 기본으로 제안한다. 실제 구현이 제공하는 명령을 저장소 README에 반영한다.

| 구성 | 책임 |
|---|---|
| 게임 규칙 | 현재 레벨, 진행도, 손님 무리, 주문 선택, 서빙·시간 초과·승급 |
| 레시피 | 재료·도구 상태와 유효 동작, 시간 및 입력 판정, 평가 결과 |
| 입력과 시계 | 포인터 이벤트를 조리 동작으로 변환하고 한 접시의 유효 시간을 계산 |
| UI와 아트 | 홀, 주방, HUD, 평가, 해금, 레이어와 피드백 표시 |
| 저장 | 완료 상태와 다음 홀을 복구할 수 있는 로컬 체크포인트 |

디렉터리명은 기존 프로젝트에 맞춘다. 레시피마다 같은 타이머나 결과 저장을 복제하지 않는다.

## 상태 계약

- **화면 상태** `title → hall → kitchen → result → hall/unlock`. 브라우저에서 복귀했을 때 `kitchen` 위에 재개 UI를 표시한다.
- **주문 상태** `waiting → active → served | expired`. 한 세션의 활성 주문은 최대 하나다. 한 번 종료한 주문은 다시 완료할 수 없다.
- **세션 데이터**. 트라이얼 상태, 레벨, 현재 무리 ID와 입장 레벨, 손님별 고유 주문 ID, 시도 메뉴, 현재 레벨 통과 메뉴, 해금 기록을 구분한다. 트라이얼과 연습 기록은 레벨 통과 집합에 섞이지 않는다.
- **이벤트 예시**. `START_ORDER(orderId)`, `RECIPE_ACTION`, `SERVE(orderId)`, `EXPIRE(orderId)`, `ACK_RESULT`. 사용 가능한 상태를 확인한 뒤 적용한다. 오래된 화면에서 온 이벤트는 현재 주문 ID와 대조한다.
- **경계 판정**. 주방 진입에서 한 번 시계를 만든다. 서빙 요청 처리 시 마감 여부를 같은 상태 전이에서 먼저 검사하고, 마감과 동시에 들어오면 시간 초과를 확정한다. 점수, 별점, 다음 손님은 확정된 결과 하나에서 파생한다.

## 시간

- 활성 시간이 증가하는 단조 시계를 사용하고, 남은 시간은 시간의 차이로 계산한다. 프레임이나 일정 간격 콜백은 화면을 갱신하는 용도로 쓴다.
- 서빙과 만료는 남은 밀리초로 판정한다. 화면의 초는 양수인 동안 올림하고, 정확히 마감에 도달하면 0으로 표시한다.
- 예열, 익힘, 물줄기 속 세척은 활성 게임 시간으로 계산한다. 결과 화면과 대기 주문에는 시간이 흐르지 않는다.
- 페이지가 숨겨지는 순간 현재 조작을 취소하고 시계를 동결한다. 이미 마감이면 만료를 먼저 확정한다. 페이지에 돌아온 뒤 플레이어가 ‘계속하기’를 눌러 주방과 레시피 시계를 함께 재개한다.
- 슬로모션, 흔들림, 화면 전환의 애니메이션은 시간을 바꾸지 않는다.

## 입력과 모바일 화면

- 조리 표면은 포인터 한 개를 추적한다. 필요한 영역에서 포인터 캡처와 `touch-action`을 사용하고, 취소·캡처 해제·화면 전환 시 제스처 상태를 정리한다.
- 터치 이벤트와 뒤따르는 클릭으로 같은 동작을 두 번 처리하지 않는다. 서빙과 다음 버튼에는 표준 버튼 의미와 포커스 표시를 유지한다.
- 입력 좌표는 현재 조리대의 경계에 맞춰 정규화한다. 껍질과 김발은 이동량을 실시간 표시하고, 손을 뗄 때만 조건을 확정한다. 회전은 그릇 중심 기준 각도 변화로 계산하며 중심부의 미세 떨림은 제외한다.
- 초기 튜닝값은 탭 대상 44×44 CSS 픽셀 이상, 칼질 정확 구간은 도마 너비 기준 가이드 중심 ±5%다. 김밥 네 번 썰기의 고른 간격은 양끝을 포함해 각 조각 길이가 목표 길이의 ±30% 이내인 상태를 기준으로 삼는다.
- 세로 기준 폭 360·390·430 CSS 픽셀과 320 CSS 픽셀의 좁은 화면을 확인한다. 위아래 안전 여백을 두고 주소창 높이 변화에도 서빙 버튼과 타이머를 볼 수 있게 한다.
- 안내·타이머·평가는 텍스트로도 표현한다. 모션 감소, 무음 상태에서도 성공과 경고를 파악할 수 있게 한다.

## 진행 저장과 복구

- 브라우저 로컬 저장소에 버전이 붙은 체크포인트 하나를 사용한다. 시작, 트라이얼 완료, 주문 결과가 확정된 시점의 다음 홀 상태와 레벨 해금 기록을 저장한다.
- 조리 중 새로고침하면 같은 미완료 주문을 주방 진입 전 상태에서 다시 시작한다. 완료 결과는 다시 지급하지 않는다. 결과 화면에서 새로고침한 경우 저장된 다음 홀 또는 해금 화면을 연다.
- 저장 형식이 손상되었거나 브라우저가 저장을 허용하지 않아도 현재 탭에서 플레이할 수 있어야 한다. 복구 불가 시 새 게임 상태를 표시한다.
- 완료 화면의 레벨 1 연습은 별도 세션이다. 다시 열면 기존 완료 체크포인트에서 재개한다.

## 빌드와 배포 확인

- 정적 빌드를 로컬 미리보기로 실행해 시작부터 해금까지 확인한다. 배포 대상이 정해지면 실제 모바일 URL에서 직접 접속과 새로고침을 확인한다.
- 기본 자동 검증 대상은 시계 경계, 중복 처리, 트라이얼과 레벨 1 진행 분리, 재도전 순서, 체크포인트 복구다. 손맛, 터치, 화면 가림은 [QA](QA.md)의 실기기 절차를 사용한다.
