# PLAN · 구현 순서

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| M0 · 기반 | 웹 프로젝트, 세로형 화면 틀, 타입과 레시피 설정, 홀·주방 화면 전환, 임시 아트 | 로컬 실행 명령과 정적 빌드가 동작한다. 시작에서 첫 주문을 고를 수 있다. |
| M1 · 필수 트라이얼 | 계란후라이 조작, 상황 안내, 60초 시계, 서빙·별점·이탈·재도전 | 한 손가락으로 트라이얼을 끝낼 수 있다. 합격과 실패의 경로를 각각 재현한다. |
| M2 · 레벨 1 | 비빔밥·김밥 조작, 최초 순서, 미통과 메뉴 재시도, 진행 저장, 레벨 2 해금 | 한 번 실패해도 레벨 1 세 메뉴를 통과할 수 있고, 완료 기록이 복구된다. |
| M3 · 모바일 검수 | 스티치 시안 적용, 임시 아트와 실제 아트 구분, 터치·안내·익힘 피드백 조정 | iOS Safari와 Android Chrome 실기기 결과를 기록하고, 빌드와 인수 테스트 결과를 남긴다. |
| M4 · 무리 영업 | 동시 입장과 대기열, 한 접시 제약, 입장 레벨별 시간, 새 메뉴와 이전 메뉴 주문 편성 | 레벨 2의 라면·떡볶이·돈가스와 두 손님의 순차 조리를 검증한다. |
| M5 · 정식 범위 | 레벨 3–5 레시피, 마스터 엔딩, 자유 영업, 후속 피드백 효과 | 전체 15개 메뉴, 최대 10인 무리, 레벨 5 완료 및 자유 영업이 연결된다. |

## 개발 시작 전·진행 중

- 스티치에서 [STITCH_PROMPT](STITCH_PROMPT.md)와 [design](design.md)로 화면 시안을 만든다. 시안 작업과 게임 규칙 구현은 독립적으로 진행할 수 있다.
- 첫 작업은 M0–M3이다. M4부터는 화면 크기와 무리 구성, 메뉴별 손질과 판정을 시안 및 플레이테스트 결과에 맞춰 세분화한다.
- M3에서는 경고를 알아챘는지, 조작이 끊기는 지점, 메뉴별 첫 시도 소요 시간을 기록하고 한 번에 한 종류의 판정값을 조정한다.
- 테스트 URL 공유 시 사용할 호스팅과 도메인은 별도로 정한다. 빌드 산출물과 실행 방법을 정리해 어디에서든 검수할 수 있게 한다.

## 전달물

- 실행 가능한 정적 웹 프로젝트와 실행·빌드 방법.
- 시안 출처, 적용 화면, 교체할 임시 아트 목록.
- 테스트 결과, 실제 검증한 기기와 브라우저, 수치 조정 내역, 남은 작업.
