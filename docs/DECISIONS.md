# DECISIONS · 합의와 검증용 기본값

## 합의한 규칙

| ID | 결정 |
|---|---|
| D01 | 제목은 〈채채의 혼밥 식당〉. 손맛 중심의 세로형 브라우저 게임. |
| D02 | 한 손가락 탭·드래그·스와이프와 동작 직전의 짧은 안내를 사용한다. |
| D03 | 필수 계란후라이 트라이얼을 먼저 플레이하고, 기본 완성 기준을 충족하면 레벨 1이 시작된다. |
| D04 | 손님은 한 무리씩 최대 10명까지 받고, 접시는 한 번에 하나씩 조리한다. |
| D05 | 다음 주문은 플레이어가 직접 선택한다. 타이머는 해당 주방에 진입할 때 시작하며 60초에서 레벨마다 5초씩 줄어든다. |
| D06 | 조금 탄 음식도 낮은 점수로 서빙 가능하다. 시간 초과 시 손님이 떠난다. 메뉴마다 별 2개 이상이면 통과다. |
| D07 | 레벨 1은 계란후라이·비빔밥·김밥 순서로 첫 주문이 나오고 미통과 메뉴를 나중에 재시도한다. 비빔밥은 채소 한 가지를 직접 씻고 썰며, 김밥은 준비된 속재료를 사용한다. |
| D08 | 레벨별 새 메뉴 모두를 통과하면 레벨업한다. 미통과 새 메뉴를 우선 주문으로 배치하고 남는 자리에 이전 레벨 메뉴를 섞는다. |
| D09 | 레벨 5의 세 메뉴 통과 뒤 마스터 엔딩과 전체 15개 메뉴 자유 영업을 연다. |
| D10 | 별도 2.5D 디자인 가이드를 사용하고 스티치에서 화면 프로토타입을 준비한다. |

## 개발을 위한 초기값

아래는 첫 버전을 실행하고 검증하기 위해 정한 값이다. 플레이테스트에 따라 조정할 수 있다.

| ID | 초기값과 이유 |
|---|---|
| P01 | 첫 범위는 트라이얼과 레벨 1까지. 레벨 2는 해금 화면만 제공해 실제 조작 검수에 집중한다. |
| P02 | 무리 최대 인원은 1·2·4·7·10명. 레벨 2 이후 첫 테스트에서는 정원을 채우고, 미시도 메뉴를 재도전보다 먼저 배치한다. |
| P03 | 무리 중간에 승급을 달성하면 바로 알리고 다음 무리부터 새 레벨을 적용한다. 자유 영업의 조리 시간은 40초로 시작한다. |
| P04 | 한 접시의 품질로 별점을 정한다. 조리 시간, 입력 횟수, 이동 허용치는 FRD와 TRD의 초기값을 적용하고 피드백을 받아 조정한다. |
| P05 | 모바일 화면이 숨겨지면 현재 제스처를 취소하고 시간을 멈춘다. 다시 보이면 탭으로 재개한다. 새로고침 시 마지막 완료 체크포인트로 복구한다. |
| P06 | 첫 화면 구조는 홀·주방 전환이다. 레벨 1 재플레이는 완료 기록이 유지되는 연습으로 제공한다. |
| P07 | 새 저장소의 기본 기술안은 Vite, TypeScript, DOM/SVG/CSS와 정적 빌드다. 배포 서비스는 실제 배포 범위에서 결정한다. |

## 후속 설계 항목

- 스티치 화면과 실제 아트 파일, 사운드 소스, 콤보 조건과 보상.
- 레벨 2–5 각 메뉴의 세부 레시피와 판정, 재료 껍질 벗기기를 포함할 메뉴.
- 7–10인 무리의 화면 배치와 플레이 시간. 정원 유지, 무리 크기 변동, 주문 편성 가중치는 테스트에서 비교한다.
